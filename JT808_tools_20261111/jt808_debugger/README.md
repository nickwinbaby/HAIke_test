# JT/T 808 参数调试工具

模拟**平台侧**的 808 调试工具，用于给设备下发参数设置（0x8103）、参数查询（0x8104 / 0x8106），并实时解析设备上行报文。

协议依据：《高新兴瑞联808协议1.0_2026-09-23》

---

## 一、启动

```bash
cd tools/jt808_debugger
python jt808_debugger.py
```

默认参数：

| 项 | 值 | 说明 |
|---|---|---|
| TCP 端口 | 1808 | **设备连这个端口** |
| 网页端口 | 8080 | 浏览器打开这个端口 |

自定义端口 / 不自动开浏览器：

```bash
python jt808_debugger.py --tcp 1809 --http 8090 --no-browser
```

启动后终端会打印本机可用于设备连接的 IP，例如：

```
 网页界面 : http://127.0.0.1:8080/
 设备接入 : TCP 1808  （设备 TSP 服务器地址改成本机 IP）
            可填地址： 10.85.20.124
```

**只需 Python 3.8+，无第三方依赖**（纯标准库）。

---

## 二、让设备连进来

设备要主动连本工具，所以要把设备的 **TSP 服务器地址 / 端口**改成本机：

| 方式 | 命令 |
|---|---|
| AT 命令 | `AT+CONFIG=TSP_SERVER_ADDR,10.85.20.124`<br>`AT+CONFIG=TSP_SERVER_PORT,1808` |
| 短信 | 按 `srv_sms.c` 的格式下发地址和端口 |
| 808 平台 | 原来的平台若可达，先下发 0x8103 把 0x0013 / 0x0018 改过来 |

改完设备重连，网页顶部「设备」数量变成 1，右侧连接列表出现 `#1 115436621651`。

> 设备连上来后会自动发 0x0100 注册。工具默认勾选「自动回 0x8001」，收到注册、鉴权、心跳、位置汇报都会自动回成功应答，省得设备卡在等应答。要让设备完整走鉴权流程，用「0x8100 终端注册应答」页签手动下发鉴权码。

## 三、界面说明

### 1. 消息头终端手机号

协议 9.1 第 8 条：消息头里的 12 位号码是 **SIM 卡 IMSI 的后 12 位**，不是 IMEI。

- 输入 15 位 IMSI → 工具自动取后 12 位
- 也支持直接输 12 位号码
- 下方实时显示 `BCD[6] = 11 54 36 62 16 51`，可肉眼核对

> 换设备只需改这个输入框，不用重启工具。
> 如果同时连了多台设备，用「发送到」下拉框指定目标连接；不选则发往最后连入的那台。

### 2. 0x8103 设置参数

参数表按协议表 12 列出全部 13 个 ID，勾选要下发的项，填值，点「下发 0x8103」。

- **范围校验**：0x0001 限 10~3600 s，0x0029 限 8~1800 s，0x0018 限 1~65535，超范围直接前端拦下，不浪费一次往返
- **0x0013 格式**：只允许纯 IP 或域名。填 `xatst.richlinkcloud.com:1808` 会被拒——协议 9.1 第 6 条明确端口只能走 0x0018
- **固件未支持**：0x0014~0x0017、0xF001 标了「固件未支持」且置灰，因为当前 `gsw_modem_validate_set_param_item()` 没实现这些 ID，下发会整帧回 MSG_ERR
- 「当前值」列在收到 0x0104 后自动填充，方便设置前先看一眼现状
- 「用当前值填充」把查到的值灌进输入框，改完再下发

### 3. 0x8104 / 0x8106 查询

- **0x8104**：消息体为空，设备回它支持的全部参数
- **0x8106**：勾选指定 ID，设备只回这几项。固件 `JT808_PARAM_ITEM_MAX` 是 8，勾超过 8 项会提示

收到 0x0104 后，日志里按参数逐条列出 ID / 名称 / 解析值 / 原始字节，同时「当前值」列同步更新。

### 4. 辅助指令

| 指令 | 用途 |
|---|---|
| 0x8001 平台通用应答 | 手动指定应答流水号、应答 ID、结果码 |
| 0x8100 终端注册应答 | 填结果码和鉴权码，走完整注册流程；「随机生成」出一段 24 位字母数字 |
| 0x8107 查询终端属性 | 设备回 0x0107，日志显示制造商 / 型号 / 终端ID / ICCID / 软硬件版本 |
| 0x8105 终端控制 | 命令字含 MCU 升级 / 切服务器 / 复位 / 恢复出厂 / 关机等 |

> 0x8105 命令参数按 GBK 编码，UDP 端口字段必须留空但保留分隔符：「地址;TCP端口;**;**制造商ID」中间是**两个连续分号**。

### 5. 原始报文

- 支持完整帧 `7E…7E`，也支持裸 `消息头+消息体`（工具自动补校验码、自动转义、自动加首尾 7E）
- 「填入当前 0x8103 报文」把界面上勾选的参数直接组帧填进来，可以复制到别处用

### 6. 收发的解析

右侧日志每条都带：

- **消息 ID / 名称 / 流水号 / 手机号 / 消息体长度**
- 校验码错误会红字标出期望值和实际值
- 展开「原始字节」看消息体和完整帧的十六进制
- 0x0104 / 0x8103 / 0x0100 / 0x0107 / 0x0200 / 0x8001 / 0x8100 都有对应解析

## 四、常见问题

**设备连不上**

1. 确认设备和 PC 在同一网段，能互相 ping 通
2. 确认 PC 防火墙放行 TCP 1808（Windows 首次运行会弹窗，要点「允许」）
3. 确认 AT 命令改完地址后设备已重连（`AT+ZIPOPEN` 是否成功）

**下发 0x8103 后设备回 result=1（MSG_ERR）**

看日志里的 `invalid param id`——说明下发的某个 ID 固件没实现，或者值超范围。当前固件支持的只有：0x0001 / 0x0010 / 0x0011 / 0x0012 / 0x0013 / 0x0018 / 0x0029 / 0x0083。

**0x0104 里的 0x0013 带了端口**

说明设备固件还是老版本。按协议应只回纯域名，端口用 0x0018 单独查。这是固件 bug，不是工具问题。

**端口 1808 被占用**

```bash
python jt808_debugger.py --tcp 1809
```
同时把设备的 TSP 端口改成 1809。

## 五、命令行参数

```
--tcp PORT     设备接入的 TCP 端口（默认 1808）
--http PORT    网页端口（默认 8080）
--no-browser   不自动打开浏览器
```
